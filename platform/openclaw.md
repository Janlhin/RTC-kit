# openclaw.md — 以 OpenClaw 为例

> 这是**适配示例**，不是安装说明。字段名、命令、约束会随版本变化，请以你所用版本的官方文档为准。
> 本文出现的所有值都是占位符。

## 已确认的通用事实

- 定时任务的定义与运行状态存在网关的 SQLite 库中，目录下的 `jobs.json` 已废弃，编辑它无效
- 创建 / 修改 / 删除任务必须走 CLI 或 API
- 载荷大致分四类：

| 载荷 | 是否调用模型 | 用途 |
|---|---|---|
| `--message`（agent turn） | 是 | 需要理解和措辞 |
| `--system-event` | 否 | 入主会话 |
| **`--command` / `--command-argv`** | **否** | 在网关主机上跑脚本，stdout 成为投递内容 |
| `--script` | 否 | 无会话的 headless 脚本 |

`--command` 这一类让「定时与状态交给普通代码」成为可能：输出静默标记则不投递，非零退出记 error。

## 六个必须核对的约束

1. **会话目标与载荷类型是否要配对** —— 某些版本里配错会被网关静默忽略
2. **时区**：显式写 `{{TIMEZONE}}`，不要靠系统时区
3. **创建后核对下次运行时间**，偏差 > 1 分钟就删掉重建
4. **静默标记**：该响的分支里绝不能出现静默标记
5. **投递**：没有登记投递目标时，只能本地渲染；禁止创建目标为空的推送任务
6. **任务条数恒定**：任何流程都只允许 `update`，不允许重新 `add`

## 推荐的触发器划分

| # | 表达式（示意） | 次数/天 | 载荷 |
|---|---|---|---|
| 1 | `{{WINDOW_A_EXPR}}` | 6 | command：`due` |
| 2 | `{{WINDOW_BCD_EXPR}}` | 18 | command：`due` |
| 3 | `{{ROLLCALL_EXPR}}` | 7 | command / message：按星期×小时门控 |
| 4 | `{{CUTOVER_EXPR}}` | 1 | command：日切 |

- 窗口 A 与其余窗口分两条，是为了让每条表达式都精确对应一个窗口，零空转
- 多个同类窗口由**一条**表达式覆盖，这是把「N 条一次性任务」压成「一条周期触发器」的关键
- 汇报/跟进/总结合一条；同一时点在不同日期类型语义不同，交给技能门控
- 日切放在首个窗口之前，且避开家用机通常关机的凌晨
- **没有任何两条落在同一分钟**

## 为什么第一阶段用 command 而不是 message

每 5 分钟唤醒一次模型、只为判断「现在该不该响」，一天几十次模型调用，且模型可能返回静默标记造成该响不响。这个判断是纯布尔逻辑，应该交给脚本：

```
触发器 → code 读 state/alarms.json → 三个条件全真才输出文案 → 平台投递
```

模型只在**用户开口时**被调用：把自然语言解析成 `add / list / reschedule / cancel`。

## 一条表达式的次数核算（示例）

```
{{WINDOW_A_EXPR}}  → 窗口 A 的 6 个时刻                     = 6
{{WINDOW_BCD_EXPR}} → 三个时段各 6 个时刻                  = 18
{{ROLLCALL_EXPR}}                                         = 7
{{CUTOVER_EXPR}}                                          = 1
合计唤醒次数 = 各窗口次数之和 + 播报次数 + 1 次日切；按你的配置核算
```

周末不在播报表里的时点会唤醒但静默（技能门控）。

## 影子模式

先把所有任务的投递设为「不投递」，只看文件证据跑两天，确认逻辑对了再打开推送。这样即使逻辑错了也不会打扰人。
