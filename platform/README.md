# platform — 运行时适配层

`rules/`、`contract/`、`skills/` 都不绑定运行时。这一层是**唯一允许出现平台命令、路径、字段名的地方**。

## 已有示例

| 文件 | 内容 |
|---|---|
| `openclaw.md` | 以某个 OpenClaw 版本为例，说明触发器、载荷类型、投递约束 |
| `jobs.example.json` | 四条触发器的声明式参数（**模板，不是可直接执行的配置**） |
| `README.md` | 本文件 |

## 适配一个新的运行时，需要回答六个问题

1. **触发器**： cron 表达式？是否支持时区？最小粒度多少？
2. **载荷种类**：有没有「跑一段代码但不调用模型」的类型？没有的话，每次唤醒都要付一次模型调用
3. **会话目标**：独立会话还是主会话？独立会话有没有写文件权限？
4. **投递**：本地渲染 / 主动推送？推送目标怎么登记？没有目标时是否会 fail-closed？
5. **静默语义**：该不说话时输出什么？出现在该响的分支里会不会被吞掉？
6. **状态存储**：任务定义存在哪？编辑 JSON 文件还生不生效？还是必须走 API / 数据库？

第 2 和第 5 条最容易造成「静默失效」：任务在跑、计数在涨、状态一切正常，但用户什么都没收到，且没有任何报错。**装完必须人为确认至少一次真响。**

## 建议的验收顺序

1. 建触发器，全部设为「不投递」的影子模式
2. 手动触发每条一次，只看文件证据
3. 跑两天，核对：唤醒次数、实际响铃次数、确认率、任务条数恒定
4. 第 3 天再打开投递，人为确认至少一条真到达
5. 之后才考虑加功能

## 一周内不许做的事

加新触发器、加新技能、往入口文件里加规则。想加的先记进 `errors.md`，一周后再看还要不要。
