# Deletion Gate

触发词：删、清掉、清理、腾空间、移除、卸载残留、批量改名。

**看完之后默认什么都不做，只出报告。** 这是设计，不是保守。

## §1 三项检查（全过才进入执行）

| # | 检查 | 怎么判 | 不过怎么办 |
|---|---|---|---|
| ① | **这对象是什么** | 有主的还是无主的？在用的还是废弃的？有安装清单 / 有 git 记录 / 被别的文件引用吗？ | 判不出来 → 停，列出来问 |
| ② | **删了能恢复吗** | 进回收站？有备份？还是永久没了？ | 不可恢复 → 必须额外提醒一次 |
| ③ | **授权够不够** | 用户是指着这一条说"删这个"，还是笼统说"清理一下"？ | 笼统授权 → 只能出报告，不能执行 |

## §2 六条红线（任何一条触线就停手）

1. **不删"有主"的东西**：有安装清单的、有 git 记录的、被配置引用的、还在用的
2. **不清整个目录**：不 `rm -rf 目录/*`、不 `del /S /Q`、不对父目录下手
3. **不删凭证类**：license、manifest、`.git`、配置文件、密钥、数据库
4. **不用永久删除**：优先回收站；Windows 上走 `SHFileOperation` 或 PowerShell 回收站 API，不用 `rm` / `del /F`
5. **被安全策略拦了就等**：原参数重试 + 用户二次确认，**不换命令、不拆批、不偷跑**
6. **拿不准就报告**：不许用"应该没用了"作为删除理由

## §3 输出格式

先给这张表，再问一句：

```
| 路径 | 大小 | 性质 | 可恢复 | 建议 |
|---|---|---|---|---|
| D:\X\abc | 1.4 MB | 卸载残留（无清单） | 可（回收站） | 删 |
| D:\X\def | 11.8 GB | 有效安装（有清单） | — | 不动 |
| D:\X\ghi | 0 B | 空目录 | 可 | 删 |
```

表格下面一行总结：`共 3 项，建议删 2 项，合计 1.4 MB；不动 1 项。要执行吗？`

**不要在这一步就执行。** 等一句明确的"删吧/执行"。

## §4 执行

1. 一个一个来，**一次最多 10 个**
2. 每删一个回报结果（`已删除` / `不存在` / `被拦截`）
3. 中途失败 → 立刻停，报告到哪一步，不要继续往下删
4. 全部完成后给一行总结 + 实际释放的空间

## §5 删除后

- 往 `errors.md` 记一条（只在出了意外时）
- 如果是可复用的判定流程（比如"怎么区分卸载残留"），问用户要不要固化成一份 SOP 存进 `{{RULES_DIR}}/` 下

## §6 禁止

- ❌ 把"清理"当成"删除"的授权
- ❌ 递归删除用户目录（Desktop / Downloads / Documents / 家目录）
- ❌ 绕过安全策略（换 API、拆成小批、写脚本执行）
- ❌ 删完才告诉用户删了什么
