# formats.md — 三套播报格式

> 格式是契约，不是建议。照抄，不自创。**空字段写「无」，不删行、不编内容。**

数据源口径：

| 类型 | 取数范围 |
|---|---|
| 汇报（report） | 今天 + 昨天 |
| 跟进（follow） | 今天 |
| 总结（summary） | 今天 + 明日预告 |

---

## 汇报

```
📊 昨日汇报 — YYYY-MM-DD
✅ 已完成：
❌ 未完成：
📝 备注：
💬 遗留建议：
```

**早报的两种产出，同一套版式：**

- **模型版（09:00）**：`rtc-report` 把 `rtc_report.py` 的素材（昨日执行结果 / 今日待办 / 用户口述）注入 prompt，模型据此写人话，落盘成 `state/reports/<日期>.md` 并投递；投完记一条投递回执（`--window report --result ok`）
- **静态版（09:10 兜底）**：没有投递回执时，`report-fallback` 窗口才接管——有模型文件就补发文件正文，没文件就用代码拼出上面的版式。**字段可以粗，但四个段头一个都不能少，也不许空着不发**

**唯一能压住兜底的是投递回执，不是文件存在。** 文件只证明模型写完了；写完了但发送失败时若静默，用户会整天没有汇报。没响过的兜底（`fireCount=0`）记 `skipped`（原因 `covered_by_receipt`）；已经响过的兜底遇到迟到回执只能止损，记 `delivered`，不能把已经发出去的文本抹成 `skipped`。截止点以**第一次实际兜底判定**为准（09:10 是窗口起点，不是墙钟硬截止；09:10:30 写好的文件会被 09:11 的第一次 tick 使用）。时刻表里 `format: report` 与 `format: report-fallback` 只能二选一，`plan` 会拒绝同时启用。

`📝 备注` 优先写用户口述（`state/notes/<日期>.md`）；没有口述就写 `tasks.md` 还剩几条。`💬 遗留建议` 只写 `tasks.md` 里顺延或反复没动的条目，不编。

## 跟进

```
🔔 助理跟进 — YYYY-MM-DD HH:00
📋 今日待办：
💬 进展：
❓ 需要做什么：
```

## 总结

```
📋 助理总结 — YYYY-MM-DD
✅ 已完成：
❌ 未完成：
📝 备注：
📅 明日预告：
```

---

## 20:00 总结额外两点

**自检行**（读运行状态账本算出来）：

```
今日闹钟：N 个窗口，响 M 次，确认 A / 漏 B / 未到 C
```

窗口数异常或 `planDate` 不是今天 → 补一句 `⚠️ 窗口表异常` 并记错误，**但不要在总结时去修它**。

**周日再加三行本周复盘**：

```
📈 本周：完成 N / 顺延 M / 反复没动 K
🔁 反复没动的：<最多 3 条>
🎯 下周优先：<最多 3 条>
```

---

## 通用约束

- 不写「以下是你的今日待办」这类引导句
- 不加鼓励语、不加情绪评价
- 条数超过 5 条 → 列前 5 条 + `…还有 N 条`
- 提醒文案控制在 2–3 行，首响必须带「回复『xx』就不响了」
- 该静默时只输出运行时约定的静默标记，不加任何解释
