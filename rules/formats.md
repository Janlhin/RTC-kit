# formats.md — 三套播报格式

> 格式是契约，不是建议。照抄，不自创。**空字段写「无」，不删行、不编内容。**

数据源口径：

| 类型 | 取数范围 |
|---|---|
| 汇报（report） | 今天 + 昨天 |
| 跟进（follow） | 今天 |
| 总结（summary） | 今天 + 明日预告 |

---

## 汇报

```
📊 昨日汇报 — YYYY-MM-DD
✅ 已完成：
❌ 未完成：
📝 备注：
💬 遗留建议：
```

## 跟进

```
🔔 助理跟进 — YYYY-MM-DD HH:00
📋 今日待办：
💬 进展：
❓ 需要做什么：
```

## 总结

```
📋 助理总结 — YYYY-MM-DD
✅ 已完成：
❌ 未完成：
📝 备注：
📅 明日预告：
```

---

## 20:00 总结额外两点

**自检行**（读运行状态账本算出来）：

```
今日闹钟：N 个窗口，响 M 次，确认 A / 漏 B / 未到 C
```

窗口数异常或 `planDate` 不是今天 → 补一句 `⚠️ 窗口表异常` 并记错误，**但不要在总结时去修它**。

**周日再加三行本周复盘**：

```
📈 本周：完成 N / 顺延 M / 反复没动 K
🔁 反复没动的：<最多 3 条>
🎯 下周优先：<最多 3 条>
```

---

## 通用约束

- 不写「以下是你的今日待办」这类引导句
- 不加鼓励语、不加情绪评价
- 条数超过 5 条 → 列前 5 条 + `…还有 N 条`
- 提醒文案控制在 2–3 行，首响必须带「回复『xx』就不响了」
- 该静默时只输出运行时约定的静默标记，不加任何解释
