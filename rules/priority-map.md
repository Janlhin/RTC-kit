# priority-map.md — 谁 / 什么值得打断你

> 这是"重要性"层。它只回答两个问题：**这事重不重要？要不要现在说？**
> 它不管你怎么回话、不管任务存在哪、不管提醒几点响。

---

## 两个维度，别混在一起

**紧急度**（要不要现在打扰你）

| 级别 | 意思 | 行为 |
|---|---|---|
| P0 | 现在就得知道，晚一小时会出事 | 立刻发消息 |
| P1 | 今天该知道 | 当天找机会说，不打断手头的事 |
| P2 | 值得记，不值得说 | 攒进汇报 |
| P3 | 噪音 | 不记、不说、不归档 |

**处理方式**（我要不要自己动手）—— 见 `auto-resolver.md`

- `auto` 自己办完再告诉你
- `draft` 起草好等你点头
- `escalate` 只上报，不动手
- `drop` 忽略

> 两者独立：P0 的事也可能是 `escalate`（很急但我不能替你做）；P2 的事也可能是 `auto`（不重要但我顺手办了）。

## 人

每个人的四字段模板（照填，别删字段）：

```
### 名字
- 为什么重要：
- 要注意什么：
- 什么情况升到 P0：
- 默认处理：
```

### 我

- 为什么重要：一切都为他服务
- 要注意什么：他的话优先于任何推断；说"不用了"就是不用了，不要再问第二次
- 什么情况升到 P0：涉及不可逆操作、钱、健康、家人的事
- 默认处理：`draft`

（其余人待填：家人 / 同事 / 合作方 / 客户）

## 默认路由（信号来了先看这张表）

| 信号 | 先去哪 |
|---|---|
| "什么时候做 X"、"提醒我 X" | `daily-task-manager` 建任务；需要到点响的进时刻表 |
| "删掉 X"、"清一下 X" | `deletion-gate` |
| "今天要做什么" | `tasks.md` + `routines.md` |
| 日常闲聊、问知识 | 正常回答，不建任务、不记 |

---

## 通常应该忽略的（P3）

- 重复的、已经处理过的
- 我自己的推测和联想
- 任何"顺便提一句"级别的信息
- 你明显已经知道的事

---

## 什么时候该改这份文件

- 出现了一个新的重要人物或项目
- 某件事反复被你判为"不重要" → 说明它该进 P3，别每次重新判
- 某件事反复上升到 P0 → 说明它的默认处理策略错了
